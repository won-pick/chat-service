# 외부 연동 합의가 필요한 항목

이 문서는 구현 완료된 API가 아닌 팀 합의용 목록입니다.

## 1. 로그인·인증

- 로그인 담당 서버, 세션 또는 토큰 방식, 검증 방법, 서버 간 인증 전달
- Chat이 검증된 회원 ID를 얻는 방식; 사용자 입력 ID는 로그인 연동 후 제거
- 회원 조회 API의 이름·전화번호 등 노출 범위 (채팅에는 필요한 닉네임만)

## 2. Market

- 실제 base URL과 상품 조회 URL, 상품 ID/판매자 ID/제목/상태 응답
- 어떤 판매 상태에서 새 채팅을 허용하는지, 상품 삭제 시 기존 대화 정책
- 오류 응답 형식, 타임아웃, 재시도 정책
- CreateChatRoomRequest에는 최종적으로 productId만 받고 판매자는 Market 응답에서 결정

## 3. Trade (최종 기능 목록 ⑧·⑨)

- 판매자가 채팅에서 결제 요청 → Chat이 판매자 확인 → Trade 거래 생성
- 실제 URL과 요청·응답, 금액 고정 또는 합의금액 정책, 거래 번호와 상태 enum
- 동일 상품의 활성 거래 수 제한, 선점 시점과 Market 실패 처리
- 서버 간 멱등 키: Chat의 재시도에서 같은 거래가 반환되도록 계약
- Trade 성공 후 Chat 저장 실패 시 같은 tradeId로 요청 메시지 복구
- 메시지 타입 TEXT / PAYMENT_REQUEST와 tradeId를 추가하는 시점은 계약 확정 후
- 카드 상태는 Trade 원본을 조회해 표시; 조회 장애를 결제 완료·취소로 해석하지 않음
- 결제하기 링크는 별도 결제 화면으로 이동; 결제 진행은 Trade → Payment
- PAYMENT_REQUESTED / PAID / COMPLETED / CANCELED 상태와 표시문구 확정
- 구매자 결제 화면 URL, 거래 취소/완료 후 동기화 방식, 사용자 권한 검증

현재 Trade 연동은 미구현이며, 임의의 결제 성공이나 모의 거래는 만들지 않았습니다.

## 4. 저장과 운영

현재 Java 메모리 방식. DB를 필수로 할지, 재시작 시 데이터 초기화를 허용할지 결정합니다.
외부 호출을 연결하면 타임아웃·실패·부분 성공·재시도 케이스를 별도 통합 테스트로 검증해야 합니다.
